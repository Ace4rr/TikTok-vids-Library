# 6. Критический разбор и решения (ревизия v0.2)

**Дата ревизии:** 2026-11-01. **Предмет:** экспертиза идей из документов 01–05 по трём критериям и фиксация решений, внесённых в документы 03, 04, 05 и новые 07–08.

## 6.1. Критерии и общий вердикт

- **Здравость** — не наивна ли идея технически и экономически; переживёт ли контакт с реальностью (поломки экстракторов, слабое железо NAS, себестоимость инференса).
- **Актуальность** — жива ли идея на конец 2026: не съедена ли конкурентами, не устарела ли технологическая база.
- **Применимость** — реализуема ли малой командой в заявленные фазы, без скрытых зависимостей от внешних сервисов.

**Общий вердикт.** Концепция здравая и актуальная: боль подтверждена, ниша «self-hosted AI-архив TikTok» по-прежнему пуста (см. 02), стек выбран правильно. Два главных риска — платформенный (хрупкость скачивания) и себестоимость AI — закрываются архитектурно, а не отказом от функций. Правки ниже уточняют механику, продукт не меняют.

## 6.2. Стратегические решения

### Р1. Self-hosted — основной режим проекта

Исходная рекомендация «SaaS-first, self-hosted потом» пересмотрена: **целевой режим — self-hosted**. Последствия:

- AI-стратегия строится от локальных моделей; облако — опциональный ускоритель, а не основа (docs/07–08);
- монетизация из главного пути становится опциональным сценарием SaaS-развёртывания того же кода (документ 02 остаётся справедливым как опция);
- «docker compose up без облака вообще» — критерий с первого релиза; режим `local_only` — по умолчанию (NFR-9).

SaaS-путь не удаляется: двухрежимность (SQLite→Postgres, очередь в БД→Redis) сохраняется, но все решения по умолчанию принимаются для self-hosted.

### Р2. Платформенный риск: трёхслойная защита

Скачивание — самый хрупкий элемент, поэтому у него три независимых рубежа:

1. **Метаданные через публичный oEmbed TikTok** — не зависит от yt-dlp, карточка (автор/подпись/обложка) живёт даже при полной поломке экстрактора.
2. **Файл через изолированный `DownloadProvider`** — yt-dlp nightly + cookies/прокси по умолчанию; альтернативный провайдер (самостоятельно развёрнутый cobalt-инстанс) за конфигурацией (FR-2.6).
3. **Embed-режим как последний рубеж** — карточка без файла остаётся полноценной единицей библиотеки.

Телеметрия доли успешных скачиваний (05.7) сохраняется — она сигнализирует о деградации раньше пользователей.

### Р3. AI-экономика: локально по умолчанию, каскад, ленивый бэклог

Каскад Tier-0 (правила, без моделей) → Tier-1 (локальные модели) → Tier-2 (облако, opt-in); один вызов LLM на видео; массовый импорт обрабатывается лениво и ночами с бюджетом. Полная спецификация — `docs/07-ai-pipeline.md`.

### Р4. Каналы приёма до нативного приложения

Telegram-бот — двунаправленный канал (приём ссылок + уведомления о готовности/дайджесты). Плюс два бесплатных канала до Фазы 2: Android PWA share target и iOS Shortcuts-рецепт («Поделиться → TokLib» = POST на `/api/inbox` с токеном). Нативное Flutter-приложение — после доказательства habit loop, не раньше.

### Р5. Данные неизменяемы; папки и экспорт — представления

Канонический путь файла зависит только от `tiktok_id`; папки библиотеки — связи в БД; дерево для Jellyfin — генерируемое представление (hardlink + NFO), пересобираемое при изменениях. Переименование папки не двигает файлы по диску.

## 6.3. Постатейный разбор идей

Вердикты: ✅ здраво, сохраняем · ⚠️ доработать · ❌ наивно, заменить.

| Идея (источник) | Вердикт | Решение |
|---|---|---|
| Embed-first: карточка живёт без файла (01, 05) | ✅ | Сохранить как есть — главный амортизатор платформенного риска |
| Изоляция `DownloadProvider` (05) | ✅ | Сохранить; добавить oEmbed-резолв и cobalt как альтернативу (Р2) |
| DB-backed очередь → Redis (05) | ✅ | Сохранить; добавить lease (`locked_by/at`) и идемпотентность стадий (05.4) |
| SQLite default → PostgreSQL (05) | ✅ | Сохранить; WAL + `busy_timeout` для одного писателя |
| sqlite-vec для векторов (05) | ✅ | Сохранить; гибрид с FTS5/BM25 обязателен — вектор один плохо ищет короткие запросы и имена авторов |
| `video.status` смешивает стадию конвейера и наличие файла (05.4) | ⚠️ | Разделить: `status` (конвейер) × `media_mode` (none/embed/audio/file) × `health` (alive/dead) |
| Путь `media/<folder-slug>/…` (03, FR-2.4) | ❌ | Хрупко: переименование папки двигает файлы. Канонический путь по `tiktok_id` + генерируемое дерево экспорта (Р5) |
| «Скачанный аудио-стрим при embed-режиме» (05.6) | ❌ | Наивно: аудио качается тем же экстрактором, что и видео. Замена: audio-only режим *хранения* (экономия диска, STT без видео) |
| few-shot из истории правок без ограничений (05.6) | ⚠️ | Заменить на закрытый словарь тегов (топ-40 таксономии пользователя) + ≤2 примера и только при замеренном приросте качества |
| Пересчёт эмбеддинга при каждой правке заметки (05.6) | ⚠️ | Debounce (закрытие карточки / ночной батч); эмбеддится составной документ «транскрипт+подпись+заметки» |
| WebSocket для статусов (05.5) | ⚠️ | Заменить на SSE: проще через reverse-proxy, проще отлаживать; WS — если понадобится двусторонность |
| Telegram-бот как MVP-канал (03, FR-1.2) | ✅ | Сохранить; добавить обратный канал — уведомления о готовности и дайджесты |
| Flutter в Фазе 2 (04) | ✅ | Сохранить; до неё — PWA share target + iOS Shortcuts (Р4) |
| Словарные автотеги в MVP (04) | ✅ | Подтверждено — это Tier-0 каскада (07) |
| «Импорт 5000 ссылок → полный AI всем сразу» (04, Фаза 3) | ⚠️ | Дорого и надолго вешает железо. Ленивая обработка: Tier-0 сразу, полный AI по требованию и ночами с бюджетом (07) |
| Квоты AI-операций (02, SaaS) | ✅ | Для self-hosted превращаются в «бюджеты» (штук/день, секунд инференса), не в деньги |
| Телеметрия деградации скачиваний (05.7) | ✅ | Сохранить; добавить метрики стадий AI (времена, доля валидного JSON) |
| Метрики «≥70% тегов без правок», «top-10 поиск» (03 §2) | ✅ | Измеримы, оставить. Если локальная модель их не даёт — меняем модель, а не метрику |
| Оценка ниши 15–150 тыс. ранних пользователей (02) | ⚠️ | Оптимистична в верхней границе; для self-hosted-первого проекта некритична, не пересчитываем |
| Дайджесты/напоминания (01, Концепция D) | ✅ | Дёшевы локально: правила + выборка, без LLM |

## 6.5. Открытые вопросы после ревизии

1. **Выбор конкретных моделей STT/LLM под язык пользователя** — решается сетом из 20 видео в Фазе 0 на профилях S/M/L (08.6); список моделей в 08 — не догма.
2. **Пороги дискового watermark (90/95%)** — проверить на реальном NAS; возможно, настраиваемый порог вместо константы.
3. **cobalt как альтернативный провайдер** — эксплуатация собственного инстанса; юрпроверка лицензии перед включением в список рекомендованных.
4. **Ожидания скорости на слабом железе** — p50 «≤2 мин до карточки» (embed-режим) достижим на любом профиле; полный AI на профиле S занимает часы — норма для self-hosted, honest-статус в UI обязателен.
5. **Языковая политика** — контент пользователя может быть мультиязычным; STT с автоопределением, саммари на языке транскрипта (флаг `content_language` в ответе LLM), UI-язык отдельно.
