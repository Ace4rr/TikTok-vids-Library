# 1. Концепция продукта

## 1.1. Проблема

Пользователи TikTok сохраняют видео «на потом»: рецепты, лайфхаки, туториалы, упражнения, идеи для дома. Со временем это превращается в проблему:

1. **Плоская очередь.** Сотни и тысячи сохранений без поиска по содержимому. Встроенные коллекции требуют ручной сортировки в момент сохранения — этим почти никто не занимается.
2. **Гниение архива.** Авторы удаляют видео или аккаунты; ссылки умирают, а вместе с ними — сохранённое. Пользователь об этом узнаёт только когда захочет вернуться.
3. **Потеря контекста.** Нет способа зафиксировать, *зачем* видео сохранено и в чём его суть. Через месяц сохранённое — шум.
4. **Нет поиска по содержимому.** Поиск работает только по подписи/хэштегам (если вообще работает), но не по тому, что говорится в видео.
5. **Замкнутость.** Сохранённое живёт только внутри TikTok: его нельзя отдать в домашнюю медиатеку (Jellyfin/Plex), в автоматизации Home Assistant, просто на диск.

## 1.2. Персоны

| Персона | Профиль | Главная боль | Что готова платить |
|---|---|---|---|
| **Собиратель рецептов/лайфхаков** | Активный пользователь TikTok, 500–5000 сохранений | «Я знаю, что сохраняла такой рецепт, но найти не могу» | Небольшая подписка за порядок |
| **Второй мозг / продуктивист** | Ведёт Notion/Obsidian/Readwise | «Я сохраняю, но никогда не возвращаюсь к содержимому» | Подписка за AI-саммари и поиск |
| **Дата-хордер / self-hosted энтузиаст** | NAS, Docker, Home Assistant | «Хочу архив, который принадлежит мне, и чтобы видео не умирали» | One-time лицензия / донаты (модель Immich) |
| **Криейтор / исследователь трендов** | Собирает референсы и конкурентов | Ручной сбор ссылок в таблицы | Pro-подписка при командном использовании |

## 1.3. Критерии сравнения концепций

- Скорость выхода MVP и стоимость разработки;
- Паническая ценность (закрывает ли боль №1 — «найти и не потерять»);
- Устойчивость к платформенному риску (блокировки TikTok, изменения API);
- Соответствие аудиторному сегменту (массовый vs энтузиасты);
- Потенциал монетизации.

## 1.4. Варианты концепций

### Концепция A. «Компаньон» — мобильный инбокс + библиотека (mobile-first)

Приложение-спутник для TikTok. Пользователь жмёт «Поделиться» в TikTok → ссылка летит в TokLib → видео автоматически обрабатывается и попадает в библиотеку с папками, тегами и плеером.

- **Ядро:** приём ссылок (share sheet / вставка), метаданные, папки + теги, плеер (embed и локальная копия), ручные заметки.
- **Сильные стороны:** самый короткий путь к ежедневной ценности; естественный habit loop (сохранил в TikTok → само приехало в библиотеку); MVP за ~6–8 недель.
- **Слабые стороны:** зависит от стабильности выгрузки видео (yt-dlp); без AI-слоя — «ещё один органайзер».
- **Аудитория:** все персоны, вход через собирателей и второй мозг.

### Концепция B. «Домашний архив» — self-hosted медиатека (NAS/Home Assistant)

Docker-сервис для домашнего сервера/NAS: веб-интерфейс, фоновая загрузка, хранение на диске, библиотека, совместимая с Jellyfin/Plex (структура папок + NFO-метаданные), интеграция с Home Assistant (сенсоры, уведомления, media browser).

- **Сильные стороны:** лояльное сообщество self-hosted (Immich, TubeArchivist доказали модель); данные у пользователя — снимает и юридические, и доверительные вопросы; видео переживают удаление из TikTok.
- **Слабые стороны:** узкая аудитория; настройка Docker — барьер; монетизация скромнее (донаты/лицензии).
- **Аудитория:** дата-хордеры, энтузиасты HA.

### Концепция C. «Перехватчик» — браузерное расширение + веб-дашборд

Расширение отслеживает просмотр TikTok в браузере, в один клик (или автоматически) сохраняет видео с метаданными; управление — в веб-панели.

- **Сильные стороны:** нулевое трение (не нужно даже делиться ссылкой); удобно для десктоп-пользователей и исследователей трендов.
- **Слабые стороны:** TikTok в браузере — меньшинство пользователей; расширения легче ломаются при редизайнах; не покрывает мобильный сценарий, где живёт основное потребление.
- **Аудитория:** криейторы, исследователи. **Вывод: не самостоятельный продукт, а поздний канал приёма ссылок.**

### Концепция D. «Второй мозг для видео» — AI-first (модель Readwise)

Главная ценность — не хранение, а **извлечение знаний**: транскрипция (Whisper), автотеги по содержимому, саммари, ключевая идея в одно предложение, таймкодовые заметки, семантический поиск «о чём было то видео про тесто на холодной воде», дайджесты «напомни непросмотренное».

- **Сильные стороны:** максимальный wow-эффект и удержание; сильная дифференциация от «простых органайзеров»; понятная платная функция (AI-квоты).
- **Слабые стороны:** стоимость LLM/STT на пользователя; AI-ошибки в тегах подрывают доверие (нужен контроль со стороны юзера); дольше в разработке.
- **Аудитория:** второй мозг, собиратели.

## 1.5. Сравнение и рекомендация

| Критерий | A Компаньон | B Домашний архив | C Перехватчик | D Второй мозг |
|---|---|---|---|---|
| Скорость MVP | ★★★★★ (6–8 нед) | ★★★☆☆ | ★★★☆☆ | ★★☆☆☆ |
| Ежедневная ценность | ★★★★☆ | ★★★☆☆ | ★★☆☆☆ | ★★★★★ |
| Устойчивость к платформенному риску | ★★★☆☆ | ★★★★★ | ★★☆☆☆ | ★★★☆☆ |
| Размер аудитории | большой | средний | малый | большой |
| Монетизация | подписка | лицензия/донаты | слабая | подписка (себестоимость AI) |

**Рекомендация: поэтапный гибрид A → D → B, C опционально.**

1. **Фаза 1 — MVP Концепции A**: инбокс ссылок, метаданные, папки/теги, плеер, ручные заметки. Ядро сразу проектируется как self-hosted-совместимое (SQLite/Postgres, Docker-friendly) — это фундамент для B.
2. **Фаза 2 — AI-слой Концепции D**: транскрипция, автотеги, саммари, ключевая идея, семантический поиск. Превращает органайзер в «Readwise для видео».
3. **Фаза 3 — Концепция B**: Docker-образ, интеграция Home Assistant, Jellyfin-совместимый экспорт, массовый импорт из архива TikTok.
4. **Концепция C** — при наличии спроса, как дополнительный канал приёма ссылок.

Такой порядок сначала доказывает привычку (A), затем отстраивает от конкурентов функционально (D), затем захватывает лояльную нишу self-hosted (B).

## 1.6. Анти-скоуп (не делаем)

- Не делаем загрузчик «без вотермарки для всех» и публичный массовый парсинг — это токсичный сегмент с юридическими рисками; только личный архив пользователя.
- Не строим соцсеть / шеринг библиотек между пользователями в v1.
- Не пытаемся «переиграть» TikTok своим фидом рекомендаций.
- Мультиплатформенность (Reels, Shorts) — в бэклоге после TikTok, не в MVP.
