# 3. Техническое задание (ТЗ)

**Проект:** TokLib — личная библиотека сохранённых TikTok-видео
**Версия документа:** 0.1 (черновик для утверждения)
**Статус проекта:** Фаза 0 (исследование/прототип)

Приоритеты требований: **[MVP]** — обязательно в первой версии; **[V1.1]** — следующий релиз; **[V2]** — горизонт планирования.

---

## 1. Общие сведения

### 1.1. Назначение

Веб- и мобильное приложение, принимающее сохраняемые пользователем TikTok-видео (ссылками), автоматически создающее их личный архив с AI-обработкой (транскрипция, теги, саммари, ключевая идея), обеспечивающее органайзацию (папки, теги), поиск (в т.ч. семантический), заметки пользователя и интеграцию с домашними экосистемами (NAS/Jellyfin, Home Assistant).

### 1.2. Глоссарий

| Термин | Определение |
|---|---|
| Инбокс | Очередь принятых ссылок до завершения обработки |
| Обогащение (enrichment) | Пайплайн: метаданные → загрузка → транскрипция → AI-анализ → индексация |
| Embed-режим | Просмотр через официальный встроенный плеер TikTok без скачивания файла |
| Ключевая идея | Автогенерируемая выжимка видео в 1–2 предложения |
| Мёртвая ссылка | Видео, удалённое с TikTok и не имеющее локальной копии |
| Tier-0/1/2 | Уровни AI-обработки: правила без моделей / локальные модели / облако по требованию (docs/07) |
| Бюджет AI | Дневной/ночной лимит AI-операций (видео), после которого конвейер деградирует на Tier-0 |
| NFO | XML-файл метаданных рядом с видео для Jellyfin/Plex |

---

## 2. Цели и критерии успеха

1. Время от «поделиться в TikTok» до появления видео в библиотеке — ≤ 2 мин (p50) для embed-режима.
2. ≥ 70% AI-тегов принимаются пользователем без правок (после первой сотни видео).
3. Поиск находит нужное видео по смыслу запроса («рецепт холодного фарша») в top-10 при библиотеке от 500 видео.
4. Локальная копия видео остаётся воспроизводимой после удаления оригинала с TikTok.
5. MVP разворачивается локально одной командой (docker compose up) — self-hosted-готовность с первого релиза.

---

## 3. Пользователи и ключевые сценарии

**US-1. Сохранение мимоходом.** Пользователь смотрит TikTok, жмёт «Поделиться → TokLib». Видео появляется в библиотеке обработанным; пользователь ничего больше не делает. *(Основной сценарий, должен работать ≤ 2 тапа.)*

**US-2. Разбор накопленного.** Пользователь запрашивает архив данных TikTok («Скачать мои данные», JSON), импортирует файл со списком избранного — сотни ссылок ставятся в очередь обработки с приоритетами.

**US-3. Поиск по памяти.** «В том видео про варенье добавляли что-то странное…» — семантический поиск по транскриптам и заметкам, не по хэштегам.

**US-4. Вечерний дайджест.** Home Assistant отправляет уведомление с 5 непросмотренными видео из библиотеки; просмотр через медиабраузер HA на телевизоре.

**US-5. Архив на своем железе.** Пользователь поднимает TokLib на NAS; видео складываются в Jellyfin-совместимую структуру и видны в его медиатеке.

## 4. Функциональные требования

### Модуль М1. Приём ссылок (инбокс)

- **FR-1.1 [MVP]** Приём ссылки через системный share sheet мобильного приложения (iOS/Android).
- **FR-1.2 [MVP]** Приём ссылки вставкой в веб-интерфейсе (одно поле + Enter) и через Telegram-бота как дешёвый MVP-канал. [V1.1] iOS Shortcuts-рецепт и Android PWA share target — приём без нативного приложения.
- **FR-1.3 [MVP]** Нормализация входа: полный URL, короткий vm.tiktok.com, share-текст с URL внутри.
- **FR-1.4 [MVP]** Дедупликация: повторная ссылка на то же видео не создаёт копию, а инкрементирует счётчик и показывает существующую карточку.
- **FR-1.5 [V1.1]** Импорт архива TikTok data export (JSON/TXT): разбор списка избранного, постановка в очередь, прогресс обработки.
- **FR-1.6 [V1.1]** Браузерное расширение: кнопка «сохранить в TokLib» на странице видео.
- **FR-1.7 [MVP]** Статусы элементов инбокса: `принято → резолвится → качается → транскрибируется → анализируется → готово | ошибка | мёртвая ссылка`; ошибки видны пользователю с причиной.

### Модуль М2. Метаданные и загрузка

- **FR-2.1 [MVP]** Резолв метаданных: автор (ник, имя, аватар), подпись, хэштеги, дата публикации, длительность, обложка.
- **FR-2.2 [MVP]** Загрузка видеофайла через изолированный провайдер скачивания (по умолчанию yt-dlp, режим nightly, поддержка cookies и прокси).
- **FR-2.3 [MVP]** Embed-режим как fallback: если файл не скачался, карточка живёт со ссылкой и встроенным плеером; загрузку можно повторить.
- **FR-2.4 [MVP]** Хранение файлов: локальная ФС; канонический неизменяемый путь `media/<id[0:2]>/<id[2:4]>/<tiktok-id>.mp4` (папки библиотеки — только связи в БД; дерево для Jellyfin генерируется отдельно, см. FR-8.2). [V1.1] Audio-only режим хранения — экономия диска при сохранении STT/поиска.
- **FR-2.5 [V1.1]** Планировщик повторных попыток с backoff; периодическая выборочная проверка живости ссылок без локальной копии (детект мёртвых).
- **FR-2.6 [V1.1]** Альтернативные download-провайдеры за конфигурацией: самостоятельно развёрнутый cobalt-инстанс, кастомные ресиверы.
- **FR-2.7 [V1.1]** Политика заполнения диска: при 90% загрузка новых файлов приостанавливается (карточки живут в embed-режиме, AI — через audio-only где возможно), при 95% — предупреждение пользователю.

### Модуль М3. Библиотека и органайзация

- **FR-3.1 [MVP]** Лента-сетка карточек: обложка, автор, подпись, статус AI-обработки, папка, счётчик заметок.
- **FR-3.2 [MVP]** Папки (вложенность ≤ 2 уровней); видео может состоять в нескольких папках.
- **FR-3.3 [MVP]** Теги: AI-теги (источник: `ai`) и пользовательские (источник: `user`); слияние, переименование, массовые операции над выделением.
- **FR-3.4 [MVP]** Фильтры: автор, тег, папка, дата сохранения, длительность, наличие локальной копии, «только непросмотренные».
- **FR-3.5 [MVP]** Отметка «просмотрено / в избранное»; сортировки (новые, старые, автор, длительность).
- **FR-3.6 [V1.1]** Смарт-коллекции: динамические выборки по правилам (тег + условие).

### Модуль М4. Просмотр

- **FR-4.1 [MVP]** Встроенный плеер: локальный файл с приоритетом, иначе embed TikTok.
- **FR-4.2 [MVP]** Полноэкранный режим; вертикальная лента «как в TikTok» для последовательного просмотра папки/коллекции.
- **FR-4.3 [V1.1]** Оффлайн-доступ на мобильном клиенте к скачанным файлам и заметкам.
- **FR-4.4 [MVP]** Переход к оригиналу в TikTok (открыть автора, видео, оставить лайк/комментарий там).

### Модуль М5. Заметки и ключевые идеи

- **FR-5.1 [MVP]** Пользовательские заметки к видео: текст, markdown, неограниченно.
- **FR-5.2 [V1.1]** Таймкодовые заметки: «на 0:47 показывает трюк» — кликабельные метки, перематывают плеер.
- **FR-5.3 [V1.1]** Выделение ключевой идеи: пользователь подтверждает/правит AI-вариант или пишет свой; отображается крупно на карточке.
- **FR-5.4 [V2]** Экспорт заметок/ключевых идей пачки видео в Markdown (для Obsidian/Notion).

### Модуль М6. AI-обработка

Каскадная модель: **Tier-0** (правила, без моделей) → **Tier-1** (локальные модели) → **Tier-2** (облако, opt-in). Экономика токенов и расходов — `docs/07-ai-pipeline.md`; провайдеры и пресеты железа — `docs/08-ai-providers.md`. Нумерация FR-6.x обновлена в ревизии v0.2.

- **FR-6.1 [MVP]** Tier-0 автотеги: словарь/правила по подписи и хэштегам, детект языка; работают без моделей и до загрузки видео.
- **FR-6.2 [Фаза 2]** Транскрипция локально по умолчанию (faster-whisper, small — минимум для русского, int8, VAD), сегменты с таймкодами; облачный STT — опция конфигурации.
- **FR-6.3 [Фаза 2]** LLM-анализ одним вызовом: теги (преимущественно из словаря пользователя, топ-40), саммари, ключевая идея, категория, язык контента — единый JSON с жёстким лимитом выхода; невалидный JSON → одна попытка ремонта → деградация на Tier-0.
- **FR-6.4 [Фаза 2]** Эмбеддинги транскрипт+подпись+заметки локальной моделью; пересчёт по debounce, не на каждый ввод.
- **FR-6.5 [MVP]** Очередь AI-задач фоновая, с приоритетами (открытая карточка → свежая ссылка → ночной бэклог) и статусом на карточке; модели конфигурируемы, режим `local_only` — по умолчанию (NFR-9).
- **FR-6.6 [Фаза 2]** Бюджеты и ленивая обработка: массовый импорт получает Tier-0 сразу, полный AI — по требованию (открытие карточки, поиск) и ночными пакетами; исчерпание бюджета = деградация, а не затык.
- **FR-6.7 [V2]** Дедуп схожих видео; «похожие в твоей библиотеке».
- **FR-6.8 [Фаза 2]** Редактирование транскрипта пользователем — чинит ошибки локального STT, улучшает поиск и повторный анализ.
- **FR-6.9 [Фаза 2]** Повторный AI-анализ выбранной моделью (точечно и массово); переиндексация эмбеддингов командой при смене модели.

### Модуль М7. Поиск

- **FR-7.1 [MVP]** Текстовый поиск по подписи, автору, тегам, заметкам.
- **FR-7.2 [V1.1]** Семантический поиск по транскриптам/саммари (гибридный: текстовый + векторный, единая строка).
- **FR-7.3 [MVP]** Операторы фильтров в поиске (`author:`, `tag:`, `folder:`).

### Модуль М8. Интеграции

- **FR-8.1 [V2→переносится в Фазу 3]** Home Assistant: кастомная интеграция (HACS) — сенсоры (новые в инбоксе, непросмотренные), сервисы (`add_url`, `search`), media_source для медиабраузера HA (просмотр библиотеки на TV, кастинг).
- **FR-8.2 [V1.1]** Jellyfin/Plex-совместимый экспорт: NFO-файлы метаданных + постер; структура каталогов под медиатеку; плагин синхронизации не нужен — достаточно ФС.
- **FR-8.3 [V1.1]** WebDAV/SMB-цель хранения (для NAS) как альтернатива локальной ФС.
- **FR-8.4 [V2]** Webhooks (новое видео готово, мёртвая ссылка) и простой REST API с токеном.

### Модуль М9. Импорт/экспорт и данные

- **FR-9.1 [MVP]** Экспорт всей библиотеки: JSON (метаданные, теги, заметки, транскрипты) + файлы архивом.
- **FR-9.2 [MVP]** Удаление видео с файлами; корзина с восстановлением ≤ 30 дней.
- **FR-9.3 [V1.1]** Импорт из TikTok data export (см. FR-1.5).

### Модуль М10. Аккаунты и приватность

- **FR-10.1 [MVP]** Режим single-user без аккаунта (токен доступа) — основной для self-hosted.
- **FR-10.2 [V1.1]** Мультиаккаунт с приглашениями (для SaaS-разворачивания).
- **FR-10.3 [MVP]** Все данные (БД + файлы) в пользовательском хранилище; кнопка «выгрузить всё»; удаление аккаунта стирает данные.

## 5. Нефункциональные требования

| № | Требование |
|---|---|
| NFR-1 | Лента 1000+ видео открывается ≤ 1,5 c (пагинация/виртуализация); поиск ≤ 1 c |
| NFR-2 | Пайплайн обогащения отказоустойчив: сбой любого этапа не блокирует остальные (перезапуск по этапам) |
| NFR-3 | Скачивание и AI — только фоновые воркеры; UI не блокируется |
| NFR-4 | Приватность: транскрипты/заметки не отправляются третьим сторонам, кроме выбранного AI-провайдера; режим «только локальные модели» доступен |
| NFR-5 | Развёртывание: `docker compose up` поднимает полный стек (API, web, воркеры, БД); SQLite по умолчанию, PostgreSQL опционально |
| NFR-6 | Мобильный клиент работает на iOS и Android из одной кодовой базы |
| NFR-7 | Резервное копирование: документированный бэкап одной папки (БД + media) |
| NFR-8 | Логи и телеметрия ошибок — опциональны и выключаемы |
| NFR-9 | AI по умолчанию локальный (self-hosted); режим `local_only` без внешних AI-вызовов; облачные провайдеры — явный opt-in с ключами пользователя (docs/07–08) |
| NFR-10 | Работоспособность на трёх профилях железа — S (NAS/слабый CPU), M (десктоп CPU), L (GPU), пресеты в docs/08; на слабом железе — деградация скорости/полноты, а не отказ функции |

## 6. Ограничения и допущения

- Скачивание видео технически против ToS TikTok; продукт — личный архив без редистрибуции; публичный доступ к файлам других пользователей исключён архитектурно.
- Стабильность yt-dlp по TikTok не гарантируется (история поломок 2025 г.); embed-режим обязателен как постоянный fallback.
- Массовый импорт из data export ограничен скоростью скачивания; очередь с приоритетами обязательна.
- Официального API TikTok для избранного нет; автосинкронизация избранного (без share sheet) — вне v1, только как экспериментальный режим с cookies пользователя.

## 7. Критерии приёмки MVP (Фаза 1)

- [ ] Ссылка, отправленная через Telegram-бота ИЛИ вставленная в веб, через ≤ 2 мин отображается карточкой: обложка, автор, подпись, теги, папка.
- [ ] Видео воспроизводится: локальный файл, при сбое скачивания — embed.
- [ ] Создание/переименование папок и тегов, перенос видео drag&drop и массовым выделением.
- [ ] Заметка сохраняется и ищется текстовым поиском.
- [ ] Удалённое с TikTok видео с локальной копией воспроизводится из библиотеки.
- [ ] `docker compose up` поднимает стек; данные переживают рестарт контейнеров.
- [ ] 200 видео в библиотеке — все интеракции без деградации (NFR-1).

## 8. Out of scope (v1)

Соцфункции (шеринг библиотек, совместные коллекции), фид рекомендаций, мультиплатформа (Reels/Shorts) — после TikTok, загрузчик «для всех желающих» (публичный сервис скачивания).

## 9. Открытые вопросы

1. Канал MVP-приёма ссылок: Telegram-бот дешевле нативного приложения — начать ли с него (рекомендуется: да)?
2. Минимальные AI-функции в MVP — решено (v0.2): словарные автотеги Tier-0 по подписи/хэштегам; полный AI-слой (STT+LLM+эмбеддинги, локально по умолчанию) — Фаза 2 по docs/07.
3. Монетизационная граница free/pro: лимит видео vs лимит AI-операций (рекомендация: AI-операции).
